# DAG 分析技能

## DAG-PR6 跨配置分配证明

依次读取 `multiseq_summary.md`、`macro_candidate_summary.md` 和
`allocation_proof.json`。只有同时满足以下条件的宏才可实施：

```text
eligible=true
allocation.allocation_proven=true
allocation.cross_config_proven=true
allocation.validation_matrix_complete=true
```

按 L1、L2、L3 顺序选择最低尚未完成的层级；存在 eligible L1 时不得选择 L2，
存在 eligible L1/L2 时不得选择 L3。必须使用证明文件给出的命名 bank、offset 和
生命周期，不得自行换用看似空闲的地址。

当前 L1/L2 已覆盖运行要求的 dim2-h4、dim4-h4、dim4-h8 与 seq2/seq6 组合。
L3 仍缺少循环交换依赖、MRF 防覆盖、逐 position 部分和空间及 FP16 累加顺序证明，
其状态为 `implementation_ready=false` 时禁止声明。

## DAG-PR5 多序列证据

首先读取 `multiseq_summary.md`、`loop_invariants.json` 和
`candidate_evidence.jsonl`。根目录 DAG 是实际 `seq6` 轨迹，`seq2/` 是实际
`seq2` 轨迹；按 Tensor+tile 语义比较两者，不按会随序列布局移动的裸地址比较。

- L1 表示中间结果的 DRAM 往返；仍按 PR4 宏或原子候选规则实现和验收。
- L2 表示输入、bias、LayerNorm 参数或单位向量的跨位置重复读取。
- L3 表示权重 tile 在不同位置上的重复装载。
- `measured_removable_read_bytes` 来自两条实际轨迹，但只是机会量上限。
- 所有 L2/L3 候选在 DAG-PR6 完成跨配置 VRF 容量、对齐和生命周期证明前均为
  `implementation_ready=false`，不得将其 ID 写成 PR4 源码声明。

优先使用精简的 `candidate_evidence.jsonl`；只有代表节点不足以确认源代码映射时，
才读取运行目录中的完整 `candidates.json`、`lifetimes.json`、`micro_ops.jsonl` 和
`edges.jsonl`。

## 输入

使用 prompt 和附件中本次运行的准确路径。闭环运行把 DAG 数据写入
`jimu-dse/results/<run>/dag_agent/`，不要假定旧的 `_out/` 路径。

按以下顺序读取：

| 优先级 | 文件 | 内容 |
|---:|---|---|
| 1 | `candidate_summary.md` | 排序后的 DRAM 往返、预计收益和 VRF 方案状态 |
| 2 | `candidates.json` | 候选证明、拒绝项、覆盖检查和分析限制 |
| 3 | `lifetimes.json` | 当前 VRF 定义-使用区间和下一次定义 |
| 4 | `summary.md` | 配置、Phase、重复模式、低 AI 阶段和候选表 |
| 5 | `phases.json` | 稳定 Phase ID、成员、输入输出及访存/FLOPs |
| 6 | `tensors.json` | Tensor 切片及其生产者、消费者节点 |
| 7 | `patterns.json` | 压缩后的重复 Phase 实例 |
| 8 | `micro_ops.jsonl` | 带稳定 ID、defs/uses 和语义标注的微操作 |
| 9 | `edges.jsonl` | 使用稳定节点 ID 表示的生产者-消费者依赖 |
| 10 | `micro_op_dag.txt` | 用于取证复核的旧版原始文本 |
| 11 | `dram_clusters.txt` | 旧版 DRAM 流量聚类表 |

`run_metadata.json` 记录 schema 版本、固件配置、ELF SHA256、数量统计和
标注方法。比较两次运行之前必须先核对它。

## 证据规则

- 优先使用 `op-000033`、`phase-0007` 等稳定 ID。
- 原始 `uses`、`defs`、事件序号和依赖边是权威证据。
- Tensor、Phase、position 和 tile 标注是启发式信息；修改前必须结合
  原始资源和固件地址宏进行复核。
- 当前无法可靠恢复 head，不能在缺少源码证据时自行推断。
- 只有固件配置和 ELF 身份均有记录时才能比较不同 DAG。
- PR3 只检查完全相同的 DRAM 地址，不检查部分重叠区间。
- `reuse` 只证明源 VRF 到最后消费者之前未被重新定义；
  `relocate` 尚未证明存在可用的新位置。
- seq2/seq6 收益是估算值，独立 probe 才是权威指标。

## 分析流程

### 1. 选择排序后的候选

先查看 `candidate_summary.md`，并且只选择一个 eligible candidate ID：

- `eligible-reuse-source-vrf`：结构上已证明可复用源 VRF。
- `eligible-requires-vrf-relocation`：必须先通过 `lifetimes.json` 和源码
  证明新的 VRF 分配，才能修改。

不得选择 `rejected` 中的项目。

### 2. 确认 Phase

查看 `summary.md` 的低算术强度表，并在 `phases.json` 中确认候选 Phase：

```text
AI = compute_flops / (dram_load_bytes + dram_store_bytes)
```

低 AI、高流量 Phase 是主要访存优化目标。重复模式意味着收益可能随
position 或 tile 成倍增加。

### 3. 确认 Tensor 切片

使用 `tensors.json` 查找同时存在生产者和消费者的 DRAM Tensor 切片，
再根据稳定节点 ID 定位 `micro_ops.jsonl` 中的节点。

### 4. 复核自动生成的保存-加载证明

保存-加载对是相同 DRAM 地址上的 `DRAM_STORE` 和后续 `DRAM_LOAD`，
且中间不存在对该地址的写入。必须在 `edges.jsonl` 或
`micro_op_dag.txt` 中确认生产者边。

```text
op-000033 DRAM_STORE defs=DRAM[0x300]
op-000150 DRAM_LOAD  uses=DRAM[0x300]
edge: op-000033 -> op-000150 via DRAM[0x300]
```

它可能把：

```text
VRF -> DRAM -> VRF
```

改为：

```text
VRF -> 保留在 VRF -> 消费者
```

### 5. 映射回固件

1. 使用节点事件序号缩小执行位置。
2. 使用 Tensor 和地址标注定位固件地址宏。
3. 在 `firmware/bert/bert_layer.c` 中找到生产者和全部消费者。
4. 根据源码复核 position/tile 地址，不能只依赖启发式标注。

### 6. 输出 VRF 生命周期证明

修改前必须给出：

```text
Selected phase ID:
Selected candidate ID:
Selected Tensor slice:
Producer node:
Consumer nodes:
DRAM address:
Intervening write:
VRF allocation:
Lifetime:
Conflicts:
PR3 VRF status:
Allocation proven:
Expected seq2 saving:
Expected seq6 saving:
```

对于 `relocate` 候选，必须检查全部重叠生命周期，证明所选 bank/row 在扩展
区间内没有定义或活跃数据。如果存在中间写入、分配未证明、VRF 冲突，或者
消费者不能直接使用缓存布局，必须主动放弃该变换。

## 必需输出

使用稳定 ID 列出候选：

```text
Save-load pairs:
  candidate-dram-0007:
  K[pos=0,tile=0]:
    op-000033 DRAM_STORE -> op-000150 DRAM_LOAD
    address=0x300, phase=phase-0007, intervening_write=no
```

随后在修改固件之前输出完整生命周期和分配证明。

## PR4 候选声明与验收

对于以 `total_bytes` 为目标的优化，必须在固件源码中准确声明一个候选 ID：

```c
// JIMU_DAG_CANDIDATE: candidate-dram-0007
```

该 ID 必须来自当前迭代的 `candidates.json`。如果源码已有旧标记，应替换旧
标记，不能再增加第二个。禁止声明 rejected ID、此前迭代的 ID 或多个 ID。

正确性与指标验证结束后，独立 PR4 门禁生成：

- `dag_diff_N.json`：声明、所选 Tensor 差异、微操作差异、seq2/seq6
  实测流量、PR3 估算和门禁原因；
- `dag_diff_N.md`：紧凑的人类可读证据报告。

G1 门禁要求：

1. 存在且只存在一个有效候选声明；
2. 所声明 Tensor 切片的 DRAM 操作数量减少；
3. seq2 实测 DRAM 流量不回退；
4. seq6 实测 DRAM 流量严格改善。

实测流量和结构化 DAG 变化方向是权威依据。PR3 启发式估算偏差较大时会记录
警告以便调查，但不会仅凭估算偏差拒绝候选。

## L1 宏候选补充规则

优先读取 `macro_candidate_summary.md` 和 `macro_candidates.json`，选择且只选择
一个 `eligible` 的 `macro-dram-l1-*`。宏可以在一轮中包含多个 L1 中间张量，
但不得混入 L2 常量缓存或 L3 权重驻留。没有可证明宏时，才从
`candidate_summary.md` 选择一个原子候选。

生成的 VRF 分配只证明导出的 DAG 配置。修改前必须把容量、对齐和生命周期证明
扩展到 dim2/dim4、seq2/seq6、单 tile 和多 tile 路径。宏声明格式为：

```c
// JIMU_DAG_MACRO: macro-dram-l1-attention
```

原子回退继续使用 `JIMU_DAG_CANDIDATE`。两种标记互斥，源码中只能保留一个。
宏门禁要求每个精确 Tensor/地址资源都减少 DRAM 操作，并拒绝宏范围外的正向
DRAM 消减。
