# VRF Cache Skill

Apply this skill to reduce DRAM traffic without changing tensor values,
arithmetic order, supported dimensions, or the generic firmware path. The
`common-constraints`, `dag-analyze`, and `self-verify` skills are mandatory.

## Core Rule: One Level per Candidate

First classify the current firmware as L0, L1, L2, or L3. Apply exactly the
lowest incomplete level below and stop. Do not combine multiple new levels in
one candidate. The independent gate must accept each level before the next
closed-loop iteration may continue.

| Level | Transformation | Primary traffic reduced |
|---|---|---|
| L1 | Keep intermediate save/load tensors in VRF | `V_WR_DRAM`, `V_RD_DRAM` |
| L2 | Preload loop-invariant constants once | repeated `V_RD_DRAM` |
| L3 | Reuse one resident weight tile across positions | repeated `M_RD_DRAM` |

This sequencing is mandatory because L1 changes tensor lifetimes, L2 extends
constant lifetimes, and L3 changes loop nesting and MRF residency.

Within L1, prefer one generated `macro-dram-l1-*` scope over a primitive
round trip. A macro may group multiple L1 intermediates when all members share
a complete capacity/lifetime proof. It is still one level and must not include
L2 constant caching or L3 weight scheduling. Use a primitive only when no
eligible macro can be proved for all validation configurations.

Before selecting any macro, require all four flags in `macro_candidates.json`:

```text
eligible=true
allocation.allocation_proven=true
allocation.cross_config_proven=true
allocation.validation_matrix_complete=true
```

Read the full per-configuration regions and proof digests from
`allocation_proof.json`. Use the generated named bank and offsets exactly.

In a closed-loop turn with `next_macro_contract.json`, selection and proof are
already complete. Implement only that contract; do not reopen the full evidence
or search for a different cache plan.

## Authoritative Capacity Model

Confirm capacities against `emulator/npu_device_mini.py::VRF_SIZES` for the
active platform before planning. Current element capacities are:

| Named bank | Mem ID | Elements | Default ownership |
|---|---:|---:|---|
| `MEM_MULTIPLY_VRF` | 1 | 64 | transient multiply result |
| `MEM_MVM_INITIAL_VRF` | 5 | 20480 | MVU input |
| `MEM_MFU_INITIAL_VRF` | 6 | 4096 | preferred long-lived cache |
| `MEM_ADDSUB_VRF_0` | 7 | 1024 | arithmetic operand/result |
| `MEM_ADDSUB_VRF_1` | 8 | 4096 | arithmetic operand/result |
| `MEM_ADDSUB_VRF_2` | 9 | 64 | additional tile accumulator |
| `MEM_MVM_ACC_VRF` | 13 | 256 | tiled-MVM partial sums |

`MEM_FILL` and `MEM_VEC_TO_MAT_ROW` are special pipeline targets, not general
cache storage. MRF holds one `NATIVE_DIM × NATIVE_DIM` tile; every
`M_RD_DRAM` or row-buffer matrix load replaces its prior contents.

Never use a numeric bank literal such as `6`, `5`, or `7`. Use the named
`MEM_*` constant so bank and offset cannot be confused.

## Mandatory Preflight Report

Before editing firmware, print a VRF allocation table in the Agent report:

```text
object | bank | [base,end) | size | alignment | first_write | last_read | owner
```

For every region prove:

1. `size` includes every position, tile and full-vector access.
2. `base % NATIVE_DIM == 0`.
3. Every access satisfies `0 <= offset` and
   `offset + NATIVE_DIM <= bank_capacity`.
4. Simultaneously live regions do not overlap.
5. Reused regions have disjoint lifetimes and the new value is written before
   its first read.
6. No operator-owned temporary bank is reused while that operator still needs
   its contents.

Use half-open intervals `[base,end)`. A cache read/write always transfers
`NATIVE_DIM` elements even when a lane mask selects fewer lanes.

If the allocation cannot be proven for every selected validation configuration,
leave the firmware unchanged.

## Dimension and Mask Invariants

- Preserve both `num_tiles == 1` and `num_tiles > 1` paths.
- Derive sizes and offsets from `NATIVE_DIM`, `hidden_size`, `seq_len`,
  `num_tiles`, `num_head`, and `head_size`; do not specialize silently to DIM2.
- Do not hard-code `0x03`, `0x0C`, or another head/full-vector mask without a
  named derivation.
- For the current 8-bit repeating lane mask, derive a full mask as
  `NATIVE_DIM >= 8 ? 0xFFu : ((1u << NATIVE_DIM) - 1u)`. Derive a head mask
  from `head_size` and the head's lane offset, and prove it fits the mask width.
- Restore any modified read/write mask before leaving the local operation.
- Preserve head layout, tile layout, DRAM layout, and externally visible final
  output locations.

## L1: Eliminate Intermediate DRAM Roundtrips

Use `macro_candidates.json` to select one eligible coherent L1 group. Fall back
to one `DRAM_STORE → DRAM_LOAD` primitive only when no macro is provable.
Every selected intermediate must not need to remain externally visible.

For every selected macro member:

1. Identify its producing pipeline/VRF and every consumer.
2. Allocate a proved region, normally in `MEM_MFU_INITIAL_VRF`.
3. Replace the DRAM store with `OP_V_WR` to the named bank and offset.
4. Replace all corresponding DRAM loads with `OP_V_RD` from the same region.
5. Preserve mandatory final output stores and externally observable data.

Prefer a small coherent group with the same lifetime, such as K/V, over a
firmware-wide rewrite. Q may remain directly in its accumulator when its
consumer immediately follows and no clobber occurs.

The generated allocation covers the required dim2-h4, dim4-h4 and dim4-h8
seq2/seq6 matrix selected by the run. Confirm that the source uses the same
symbolic offsets and lifetime boundaries. The independent DAG gate requires
every exact Tensor/address member to decrease and rejects DRAM reductions
outside the declared macro scope.

L1 must not change weight load scheduling.

For `macro-dram-l1-transient-scratch-bank13`, replace only the two generated
transient round trips:

1. Replace the softmax `SCRATCH_ADDR` store/load with a write/read of the
   contract's `transient_allocation`.
2. Replace the LayerNorm `_SCRATCH + num_tiles*8` store/load with the same
   slot; never assume this address is always `0x510`.
3. Preserve every operation between each write and read.
4. Do not access the retained-Q region at or above `seq_len*NATIVE_DIM`.

## L2: Cache Repeated Read-Only Data

Only begin L2 when the accepted input already satisfies L1.

Select one eligible `macro-dram-l2-*`. It may cover invariant bias,
LayerNorm gamma/beta and unit vectors, or repeated input-position values. Every
member is read more than once and never written by firmware in each proof DAG.

1. Preserve the first compulsory DRAM read of each exact value.
2. Write that value to its generated VRF region before the second use.
3. Replace only subsequent DRAM reads in the macro scope with cache reads.
4. Preserve the original lane layout and FP16 boundary behavior.

Use the exact per-configuration member list: tile and position counts may differ
between dim2-h4, dim4-h4 and dim4-h8. Derive source loops symbolically rather
than spelling out the reference seq6 members.

L2 must not reorder matrix multiplication or accumulation.

## L3: Weight-Stationary Scheduling

Only begin L3 when the accepted input already satisfies L1 and L2. L3 is
optional: skip it if MRF residency or per-position partial-sum storage cannot be
proved.

Do not attempt an L3 macro unless its generated contract has
`status=ready`, `implementation_ready=true`, and complete configuration proof
digests. Ready K/V and Q contracts are deliberately narrower than the blocked
firmware-wide weight-stationary opportunity.

For a repeated projection:

1. Keep tile-row/tile-column traversal in the same mathematical accumulation
   order for each output.
2. Load one weight tile into `MEM_MATRIX_RF`.
3. Process the applicable positions while that tile remains resident.
4. Store each position's partial sum in a distinct, capacity-proven region.
5. Ensure the inner position loop contains no matrix load or row-buffer
   operation that clobbers the resident tile.
6. Apply bias, activation, residual and normalization at the same numerical
   boundary as before.

Changing only the interleaving between independent positions is allowed.
Changing the tile-column accumulation order for one output is forbidden because
it can change FP16 rounding.

For `macro-dram-l3-kv-weight-stationary`, implement exactly this bounded form:

1. Populate the existing X cache once for every position.
2. For K, then V, loop `tr`, `tc`, then `position`.
3. Load W[tr,tc] once before the inner position loop.
4. Keep one partial vector per position at the contract's aligned
   `MEM_MVM_ACC_VRF` offsets.
5. Permit only vector operations in the position loop; `M_RD` and
   `M_RD_DRAM` would clobber the resident weight tile.
6. Preserve `tc=0..num_tiles-1` for each position and add bias only after its
   final `tc` partial sum.
7. Write K/V to their existing bank-6 layouts so attention consumers and all
   later phases remain unchanged.

For `macro-dram-l3-q-weight-stationary`, implement exactly this bounded form:

1. Reuse the populated X cache and loop `tr`, `tc`, then `position` for Q.
2. Use the contract's `partial_sum_allocation` for in-progress Q vectors.
3. After bias, write every completed Q[pos,tr] to the disjoint
   `retained_output_allocation`; do not keep Q weights live across attention.
4. Finish all Q positions before entering per-position attention.
5. Make attention read Q[pos,tr] from the retained bank-13 region. K.T and V.T
   may then clobber MRF without invalidating Q.
6. Preserve each output's `tc=0..num_tiles-1` accumulation and bias boundary.

For `macro-dram-l3-self-output-weight-stationary`:

1. Finish attention for every position first and replace only dead Q[pos]
   entries with contexts in state A.
2. Run SELF_OUTPUT as `tr`, `tc`, then `position`; keep `tc` order unchanged.
3. Read contexts from state A and write completed SELF_OUTPUT vectors to the
   separate state B. Never overwrite state A during this matrix phase.
4. Begin residual1 only after every SELF_OUTPUT position is complete.

For `macro-dram-l3-ffn-intermediate-weight-stationary`:

1. Finish residual1 and LN1 for every position and write each normalized
   vector to state A before loading an FFN intermediate weight tile.
2. Run FFN_INTERMEDIATE as `tr`, `tc`, then `position`, reading state A and
   writing the completed result to state B.
3. Preserve `tc=0..num_tiles-1`; add bias only after the final `tc`, then apply
   GELU before the state-B write.
4. Keep every `L2X_CACHE[pos]` entry unchanged until residual2. Temporary LN1
   pipeline slots must not overlap a still-live X entry.
5. Begin FFN_OUTPUT only after every GELU position is complete.

For `macro-dram-l3-ffn-output-weight-stationary`:

1. Treat state B as the immutable GELU input for the entire matrix phase.
2. Run FFN_OUTPUT as `tr`, `tc`, then `position`, loading each weight tile
   exactly once and writing completed output vectors to state A.
3. Preserve `tc=0..num_tiles-1` and add bias only after the final `tc`.
4. After every FFN_OUTPUT position is complete, add the corresponding retained
   `L2X_CACHE[pos]`, run LN2, and write the required final DRAM output.
5. Do not remove compulsory weight, parameter, input, or final-output traffic;
   reaching the generated floor is not permission to alter observable I/O.

## Forbidden Transformations

- Do not modify tests, emulator, ISS, hardware model, or DRAM initialization.
- Do not delete generic multi-tile support.
- Do not replace named banks with raw numeric IDs.
- Do not infer capacity from an apparently unused high offset.
- Do not overlap live cache regions.
- Do not remove required final output writes.
- Do not change FP16 operation or accumulation order.
- Do not weaken validation to make a level pass.

## Acceptance after Each Level

Run the exact independent gate from the prompt. For production BERT acceptance,
use validation scope `all`: 6 passed and 0 skipped.

For G1 metric acceptance:

```text
seq2 total_bytes: candidate <= iteration input
seq6 total_bytes: candidate <  iteration input
seq6 instr_count: enforce the configured limit only when instruction_gate=on
```

Correctness is checked before metrics. A candidate that improves seq6 while
regressing seq2 is rejected. A candidate that applies two new levels at once is
also non-conforming even if tests pass.

The instruction gate is a policy switch, not a correctness rule. When enabled,
the default limit is `candidate <= input × 1.10`. When disabled, instruction
counts are still recorded and reported but do not reject an otherwise valid
candidate. Never claim that disabling this gate proves end-to-end performance.
