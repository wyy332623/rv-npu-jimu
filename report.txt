NPU 固件的 Agent 重构

一、总览

闭环优化流水线（jimu-dse）中 AI Agent 对 NPU 固件 firmware/bert/bert_layer.c （一层 BERT encoder）自动完成了两轮优化。

流水线遵循 PROBE→ANALYZE→AGENT→VALIDATE→DEPLOY 的闭环：先在 seq=2 与 seq=6 两种配置下记录 DRAM 流量并生成 micro-op DAG，再由 Agent 结合 DAG、DRAM cluster 分析与skill（vrf-cache / dim-optimize）生成候选补丁，最后用“numpy 参考→模拟器→DAG 审计”校验接受或拒绝。全程 Agent 只修改 bert_layer.c，不触碰模拟器、ISS 与测试。

二、G1：DRAM 数据通路重构（dim=2，vrf-cache）

G1 的核心是 DRAM 优化，致力于减少外存读写、提升访存性能，同时保持 NATIVE_DIM=2、hidden_size=4 的多切块模式不变。

2.1 优化背景：为什么中间变量往返 DRAM 是瓶颈

在固件原本的逻辑中，算子之间的数据通路较低效：大量中间变量（K、V、Q、Z、Self-Output、LayerNorm 等）被迫写入外部 DRAM 的 Scratch 区域，随后又被紧接着的下一级算子读出，造成严重的访存浪费。DAG 分析把这类“DRAM_STORE→DRAM_LOAD 同地址、中间无改写”的边识别为 save-load 对，其算术强度（AI）极低（0.0~1.2），是典型的访存受限热点。

Skill 策略：引入向量寄存器堆（VRF）作为片上高速缓存，大幅降低内存流量。片上 MFU_INITIAL_VRF（mem6）容量 4096 元素，而 dim2/hidden4/seq6 全部 K+V 也仅约 48 元素，缓存这些中间量占用不到 3%，容量绰绰有余——这为“用片上缓存彻底替换 DRAM 往返”提供了物理前提。

2.2 新增 mvm_tiled_vrf 函数

G1 重构新增了 mvm_tiled_vrf 函数。传统矩阵-向量乘法从 DRAM 抓取输入向量，而该函数允许输入向量的基地址指向片上 VRF。引入此机制后，级联算子之间的中间结果可以全程留在寄存器中，无需访问外部内存。

static void mvm_tiled_vrf(uint32_t mat_dram_base, uint32_t vec_vrf_base,
                           uint32_t num_tiles, uint32_t bias_dram_base)
{
    // 配置标量寄存器，由软件接管多块分发
    SEND_SI(OP_S_WR, REG_TILE_ROWS_ADDR, 1);
    // ...
    for (tc = 0; tc < num_tiles; tc++) {
        // [核心优化]：直接从片上 VRF 缓存读取输入向量块
        SEND_SI(OP_V_RD, vec_vrf_base + tc * NATIVE_DIM, 0);
        SEND_SI(OP_V_WR, MEM_MVM_INITIAL_VRF, 0);
        // ...执行硬件乘加并累加...
    }
}



2.3 中间变量的片上缓存策略

基于 mvm_tiled_vrf 与 NPU 内置指令，代码针对不同变量实施了差异化的存储策略。

2.3.1 K / V 向量缓存化与地址映射

原本通过 save_row_tiles 写回 SAVE_K_BASE / SAVE_V_BASE 的指令被移除，取而代之的是计算片上偏移量 cache_off，用 SEND_SI(OP_V_WR, MEM_MFU_INITIAL_VRF, cache_off) 把 K、V 写入寄存器；V 在计算出 K 的整体大小后叠加一个偏移，存放在 K 之后。下面是优化前后的对比：

优化前（写回 DRAM，注意力阶段再读回）：

/* 基线：K 投影结果经 save_row_tiles 落到 DRAM 的 SAVE_K_BASE */
save_row_tiles(num_tiles, SAVE_K_BASE + pos * num_tiles * 8,
                MEM_ADDSUB_VRF_0, MEM_ADDSUB_VRF_1);
...
SEND_LO(OP_V_RD_DRAM, SAVE_K_BASE + p * num_tiles * 8 + tr * 8);  /* 注意力阶段读回 K */

优化后（直接搬到片上 VRF，按位置索引排布）：

/* K：写入 mem6，偏移 = 位置 * num_tiles * NATIVE_DIM */
uint32_t cache_off = pos * num_tiles * NATIVE_DIM;
SEND_SI(OP_V_RD, MEM_ADDSUB_VRF_0, 0);
SEND_SI(OP_V_WR, MEM_MFU_INITIAL_VRF, cache_off);
SEND_SI(OP_V_RD, MEM_ADDSUB_VRF_1, 0);
SEND_SI(OP_V_WR, MEM_MFU_INITIAL_VRF, cache_off + NATIVE_DIM);

/* V：紧跟在整个 K 区之后，避免地址冲突 */
uint32_t v_base_off = seq_len * num_tiles * NATIVE_DIM;
uint32_t cache_off  = v_base_off + pos * num_tiles * NATIVE_DIM;
...
uint32_t k_off = p * num_tiles * NATIVE_DIM + tr * NATIVE_DIM;  /* DRAM 读换成 VRF 读 */
SEND_SI(OP_V_RD, MEM_MFU_INITIAL_VRF, k_off);

mem6 的地址被规划为三段：[K 区: seq×tiles×dim] [V 区: seq×tiles×dim] [复用槽 VRF_CACHE_OFF]。K/V 按 (位置, 瓦片行) 二维索引线性展开，保证注意力阶段对任意位置 p、瓦片行 tr 都能算出唯一片上偏移。

2.3.2 Q 向量即算即用与“延迟清零”

Q 向量不再分配独立缓存区：计算出 Q 后直接保留在累加器 MEM_ADDSUB_VRF 内，注意力分数阶段直接读取，用完即清零供下级流水写入。这里有一个易错点——Q 与注意力上下文 context 复用同一块累加器，基线为给 context 累加腾出清零后的累加器，被迫先把 Q 落 DRAM 再读回。Agent 发现两者生命周期并不重叠，只要把“清零”推迟到 Q 被消费之后即可，Q 全程留在片上，省掉一存一取：

/* 计算 Q —— 保留在 ADDSUB_VRF，不落 DRAM */
mvm_tiled_q(...);
...
SEND_SI(OP_V_RD, acc_vrf, 0);      /* 注意力分数阶段直接读 Q */
...
/* Q 已被消费 —— 此刻才清零累加器，供 context 累加 */
SEND_SI(OP_V_RD, MEM_FILL, 0);
SEND_SI(OP_V_WR, acc_vrf, 0);

2.3.3 BERT 主干链路暂存区消除：单槽复用

原固件预留了大量 0x600 以上的物理地址存放中间层结果，现已被统一的片上偏移量 VRF_CACHE_OFF 接管，写在 K、V 之后。注意力上下文 Z、自输出 SO、LayerNorm1 输出、GELU 激活这四个中间量在时间上依次产生、各自被下一级立即消费后即失效，活跃区间互不重叠，因此共用同一块区域也不会冲突——这等价于编译器寄存器分配中“活跃区间不冲突即可复用同一寄存器”的思想。

#define VRF_CACHE_OFF   (2 * _SEQ_LEN * _NUM_TILES * NATIVE_DIM)  /* K+V 之后 */
...
/* Z（注意力上下文）写入复用槽 */
SEND_SI(OP_V_WR, MEM_MFU_INITIAL_VRF, VRF_CACHE_OFF + tr * NATIVE_DIM);
/* 自输出投影用 mvm_tiled_vrf 从同一槽把 Z 读进来做输入向量 */
mvm_tiled_vrf(_PROJ_BASE + 3 * _STRIDE, VRF_CACHE_OFF, num_tiles,
              _PROJ_BASE + 3 * _STRIDE + _MAT_SIZE);

三、G3：单块重构与计算效率优化（dim=4，dim-optimize）

本轮 goal 为 combined（dim=4 / hidden=4 / num_head=2）。由于我们已完成 G1 优化，其实际收益以 G2（计算效率优化）为主：通过单块架构重构消除分块循环开销，实现计算效率飞跃。主指标是 test_pass。代码见 candidate_best.c，改动见 diff_2.patch。

3.1 优化背景与目标

在默认基线中，硬件维度 NATIVE_DIM=2 小于隐藏层维度 hidden_size=4，NPU 必须在软件层面分块完成一次完整矩阵运算，多级循环带来较大运算与访存开销。G2 的核心是计算效率优化：把 NATIVE_DIM 调到 4 以匹配 hidden_size，一次性完成运算。Skill 策略为 dim-optimize（单块投影重构，消除软件循环），可将每次投影的 MV_MUL 从 4 次降到 1 次，并大幅减少 M_RD_DRAM（权重加载）次数。

需要强调的关键前提：基线固件本是按 dim=2 多瓦片设计的，直接编到 dim=4 时运行时 num_tiles=1，但多块/多头代码路径内藏 Bug，产生的是错误数值而非崩溃（silent wrong result）。因此本轮真正的价值不只是“省”，而是“重构 + 查错”——把这份会静默算错的固件，改成正确且精简一半（657→327 行）的单块实现。

3.2 从分块到单块：剥离循环与简化访存

固件的执行逻辑由“嵌套循环”转变为“直线型流水线”。在核心乘法函数 mvm_tiled_vrf / mvm_tiled_q 中，原有的 for (tc=…) 与 for (tr=…) 被完全移除，也无需再维护备用累加器（如 MEM_ADDSUB_VRF_2）：

static void mvm_tiled_vrf(uint32_t mat_dram_base, uint32_t vec_vrf_offset,
                           uint32_t num_tiles, uint32_t bias_dram_base)
{
    (void)num_tiles;                       /* 单块：num_tiles 恒为 1 */
    SEND_SI(OP_S_WR, REG_TILE_ROWS, 1);
    SEND_SI(OP_S_WR, REG_TILE_COLS, 1);
    SEND_SI(OP_S_WR, REG_ITERATIONS, 1);

    SEND_SI(OP_V_RD, MEM_MFU_INITIAL_VRF, vec_vrf_offset);  /* 输入向量取自片上 VRF */
    SEND_SI(OP_V_WR, MEM_MVM_INITIAL_VRF, 0);
    SEND_SI(OP_V_RD, MEM_MVM_INITIAL_VRF, 0);

    SEND_LO(OP_M_RD_DRAM, mat_dram_base);   /* 一次加载完整 4x4 权重块 */
    SEND_SI(OP_M_WR, MEM_MATRIX_RF, 0);
    SEND_SI(OP_MV_MUL, 0, 0);               /* 一次 MV_MUL 得到全维结果 */

    SEND_SI(OP_V_WR, MEM_MVM_ACC_VRF, 0);   /* 偏置加：单块单行 */
    SEND_LO(OP_V_RD_DRAM, bias_dram_base);
    SEND_SI(OP_V_RD, MEM_MVM_ACC_VRF, 0);
    SEND_SI(OP_VV_ADD, 0, 0);
    SEND_SI(OP_V_WR, MEM_ADDSUB_VRF_0, 0);
}

诸如 save_row_tiles、load_and_add_row_tiles、apply_layernorm 等函数也同步剥离了 num_tiles 参数及遍历循环，只需一次向量读写或一次 SUB_LAYERNORM 即可覆盖完整维度。这是代码量从 657 行骤降到 327 行的主因。

3.3 注意力机制精细化：逐头掩码（Per-Head Masking）

在单块模式下，多个注意力头的数据被紧密堆叠在同一个硬件物理维度中。为防止头间数据污染，重构引入动态掩码机制：通过头索引 h 与头大小 head_size 移位生成 read_mask / write_mask，用 SEND_SI(OP_S_WR, REG_READ_VECTOR_MASK, read_mask & elem_mask) 指示硬件精准屏蔽非本头字段。

uint32_t head_size      = NATIVE_DIM / num_head;      /* = 2 */
uint32_t heads_per_tile = NATIVE_DIM / head_size;     /* = 2 */
for (h = 0; h < heads_per_tile; h++) {
    uint32_t head_shift = h * head_size;                       /* 0 或 2 */
    uint32_t read_mask  = ((1 << head_size) - 1) << head_shift; /* 0x3 / 0xC */
    uint32_t write_mask = (1 << head_size) - 1;                /* 0x3 */
    ...
    SEND_SI(OP_S_WR, REG_READ_VECTOR_MASK, read_mask & elem_mask);   /* 只读本头元素 */
    ...
    SEND_SI(OP_S_WR, REG_WRITE_VECTOR_MASK, write_mask & elem_mask);
    SEND_SI(OP_V_WR, MEM_ADDSUB_VRF_0, write_off);              /* 写回本头元素槽 */
}

3.4 三处隐藏 Bug

单块 + 多头改造之所以困难，在于它引入了三处“只产生错误数值、不报错崩溃”的隐蔽 Bug。Agent 通过追踪 NPU 硬件状态逐一定位并修复，这比模板化的数据搬运更能体现其对微架构的理解。

Bug 1 —— VRF 缓存的 bank / 偏移混淆

根因：mvm_tiled_vrf 误把 VRF_CACHE_OFF 当成 bank 号（bank 16 = MEM_SPU_ABSMAX_REDUCE），而正确应为 bank 6（MEM_MFU_INITIAL_VRF）+ 该值作为偏移。症状：自输出、FFN 等后续投影全部读到垃圾数据。

/* 错误：VRF_CACHE_OFF 被当作 bank 号 → 落到 bank 16 */
// SEND_SI(OP_V_RD, VRF_CACHE_OFF, 0);
/* 正确：bank = MEM_MFU_INITIAL_VRF(6)，VRF_CACHE_OFF 作偏移 */
SEND_SI(OP_V_RD, MEM_MFU_INITIAL_VRF, vec_vrf_offset);

Bug 2 —— MEM_FILL 累加器清零放错位置

根因：累加器清零本应在头循环“之前”只做一次；基线放在 per-head 循环“之内”，导致进入第二个头时把第一个头刚算出的 context 清零摧毁。修复：将清零上提到循环外，每个头写各自的元素偏移。

/* 修复：清零移到头循环之前，只做一次 */
SEND_SI(OP_V_RD, MEM_FILL, 0);
SEND_SI(OP_V_WR, MEM_ADDSUB_VRF_0, 0);
for (h = 0; h < heads_per_tile; h++) {
    ...  /* 每个头写到 write_off，不再互相清零 */
}

Bug 3 —— WRITE_VECTOR_MASK 用后未复位

根因：最后一个头写完 context 后，写掩码停在 write_mask（如 0x3，只覆盖 4 元素中的前 2 个）。之后所有 V_WR（缓存写、投影、GELU）都只写一半元素，静默污染索引 2、3。修复：头循环结束后把写掩码恢复成全 1（0xFF）。

    }  /* end head loop */
    /* 恢复全掩码，防止后续 V_WR 只写部分元素 */
    SEND_SI(OP_S_WR, REG_WRITE_VECTOR_MASK, elem_mask);   /* 0xFF */

1. 项目背景与整体结构

核心数据链路：

RISC-V 固件 (.elf) → MiniRV64 ISS → NPU 设备 (Python) → C 内核库 (libnpukernels.so)

• 固件是编译后的裸机 RISC-V ELF，由 ISS（指令集模拟器）逐条执行；

• 固件通过 MMIO 向 Python 的 NPU 设备发 NPU 指令；

• Python 设备负责指令解码 / 寄存器 / 控制流，真正的数值计算下放给 C 内核库；

• numpy golden reference 仅供测试当"标准答案"，不属于模拟器本身。

2. 优化系统（jimu-dse）如何运作

2.1 核心哲学：省访存，不省算力

NPU 上 FLOPs 便宜、DRAM 往返贵。 优化的唯一北极星是"降低 DRAM 流量"， 用算术强度 AI = FLOPs / 搬运字节数找瓶颈，把 AI 低（<1.0）的访存簇干掉。

内存层级类比：

• DRAM = 楼下大仓库（慢、大）

• 片上寄存器 VRF/MRF = 桌上小抽屉（快、小）

• 优化 = 少跑仓库。

2.2 闭环流程

PROBE → ANALYZE → AGENT → VALIDATE → DEPLOY → (LOOP)

3. 当前进展

• 已跑过的优化目标（goals）：

• G1（dram-optimization）：DIM=2，vrf-cache，主指标 total_bytes——不动分块，只砍 DRAM 往返。

• G2（compute-optimization）：DIM=4，dim-optimize——消除分块。

• G3（combined）：DIM=4，dim-optimize vrf-cache，主指标 test_pass。

•已完成 G1 + G3，把 BERT 的分块优化掉了。

num_tiles:1, mv_mul_per_projection:1, total_projection_mv_mul:36, heads_per_tile:2, total_bytes:5472

—— 与 dim-optimize 的 cost model 目标一字不差。

• L4 补偿已在 adder 固件跑通：全项目只有 adder_130p.c / adder_140p.c 实现了分块 SPU softmax

（SPU_MAX_REDUCE + SPU_ADD_REDUCE + V_EXP + S_RECIP + 补偿）；BERT 仍用整块 V_FUNC。

• adder 移植期间修复了共享模拟器的多处缺陷：V_EXP（原为空操作）、SPU 归约（改为累加）、

S_RECIP/S_SQRT（原为桩）、V_SIGM（原缺失）、SRF 未清零。这些修复被整个项目共享。

• 已有一份人工报告：jimu-dse/results/NPU固件优化重构报告.docx。

4. 核心问题

4.1 负载锁死（只服务 BERT）

• 所有 goal.sh 写死 BASELINE_FILE="jimu-dse/baseline/bert_layer.c"；

• self-verify / dag-analyze 写死 tests/integration/test_bert_e2e.py；

• 流水线没有"负载"这一抽象——它只认识"那个 BERT 层"。

4.2 固件锁死（只优化 bert_layer.c）

• skill 只改 firmware/bert/bert_layer.c；

• 无法作用于 adder 固件或任何其他算子控制固件。

4.3 skill = 机械替换，而非技能说明

• inc_folding 本质是一个 diff：一张"第 221 行把 A 换成 B"的表，还明说"只改列出的 8 处"。

它编码的是这一个文件的标准答案，不是可迁移的规则。

• skill 写死 行号、BERT 函数名（mvm_tiled_q、dot_product_attention、apply_layernorm）、

BERT 张量地址（0x300=K, 0x400=V）。

• 内部自相矛盾：dag-analyze 已能通用地找出存取对，但 inc_folding 绕过它、改用写死行号。

→ "探测通用、改写锁死"。

• 与项目自身理念冲突：README 声称 skill 应是带 trigger/preconditions/transformation/cost_model

的结构化规格；设计文档 §5.4 更要求 L4"从算子数学 + 原语语义推导，而非模板匹配"。

但落地的 skill 大多是写死步骤的自由文本。

4.4 深度绑定当前 NPU 设计（不可移植）

skill 把优化原理和这台 NPU 的 ISA/微架构焊在一起：

• 绑具体 opcode（V_WR_DRAM_INC/V_RD_DRAM_INC = 22/23）、指令格式（SEND_SI/SEND_LO）；

• 绑硬件"事实性怪癖"：INC 变体必须用 LO 格式，用 SI 会让 Q 输出全 0；

• 绑寄存器堆容量：MFU_INITIAL_VRF = mem 6 = 4096 元素、ADDSUB_VRF_*、MATRIX_RF；

• 绑寄存器号：REG 20 = 精度模式、REG 1/2/3 = tile 行/列/批量。

换一台 NPU（容量/opcode/tile 尺寸不同），现有 skill 绝大多数直接失效。

优化原理通用，但编码只属于这台 NPU。

4.5 算子不具体

优化对象是"整个 BERT 层"，而非单个算子（matmul / softmax / RMSNorm / SiLU / attention）。

无法针对某个算子做针对性优化，也无法跨负载复用算子级优化。

4.6 硬件-固件协同闭环

项目名为 "FW-HW co-optimization"，但实际几乎全是固件单边优化：

• DAG/cluster 分析只被用来改固件，从没被用来反推 ISA；

• 缺"固件反复回退某算子 → 量化代价 → 提议新增硬件指令"的反馈支路。

4.7 skill 类目大量空缺

• fusion/（算子融合）、tiling/（循环分块）、compensation/（近似补偿）三个类目全空；

• L3 除 dim-optimize 外只有命名；L4 无任何 skill。

4.8 L3/L4 的 regime 冲突

• dim-optimize（L3） 把矩阵缩进单 tile——softmax 一次装得下，不需要补偿；

• L4 补偿 恰恰是大到单 tile 装不下时才用。

• 当前 BERT 已是单 tile（G3 之后），L4 没有优化对象——必须先放大 benchmark 到多 tile。

7.1 L3 路线

1. 敏感度画像：借 adder 的 FP16 研究方法，逐张量/逐层测 BERT 权重对 FP16/BFP 的敏感度。

2. 写 hw/precision-select skill：按敏感度 + DRAM 代价决定每张量用 BFP/FP16，切 REG 20。

现在 REG 20 只能整层切，按张量需先确认模拟器/硬件粒度支持。

3. 验证：max_diff 在容差内 + DRAM 降幅，跨 seq 回归。

4.（后续）tile/batch 配置搜索（REG 1/2/3）+ 预测性 cost model；泛化 dim-optimize 为形状驱动。

7.2 L4 路线（需先扩规模）

0. 扩 benchmark 到多 tile（hidden > NATIVE_DIM 或更大 seq_len）——L4 的前提。

1. 把 V_EXP 接进 BERT 固件通路（模拟器已支持，adder 在用）。

2. 移植 adder 分块 SPU softmax，替换 BERT 多 tile 路径的整块 V_FUNC/SOFTMAX。

3. 写 compensation/tiled_softmax skill（推导式，按 §5.1 四阶段：近似→合并→修正→验证）。

4. 验证：max_diff < 容差，且确认能跑通整块 softmax 跑不了的多 tile 形状。

5.（依赖 1-4）分块 attention（在线/流式，FlashAttention）+ compensation/tiled_attention skill。

6.（收尾）tiled_layernorm、bfp_tile_approx（衔接 L3 精度）、approx_gelu_boundary。
