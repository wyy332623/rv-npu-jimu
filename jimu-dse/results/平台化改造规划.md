## 1. 项目背景与整体结构

`rv-npu-jimu` 是一个**开源 FPGA NPU（神经网络加速器）功能模拟器**。核心数据链路：

```
RISC-V 固件 (.elf) → MiniRV64 ISS → NPU 设备 (Python) → C 内核库 (libnpukernels.so)
```

- **固件**是编译后的裸机 RISC-V ELF，由 ISS（指令集模拟器）逐条执行；
- 固件通过 **MMIO** 向 Python 的 NPU 设备发 NPU 指令；
- Python 设备负责指令解码 / 寄存器 / 控制流，**真正的数值计算下放给 C 内核库**；
- numpy golden reference 仅供测试当"标准答案"，不属于模拟器本身。

### 1.1 关键目录

| 目录 | 作用 |
|---|---|
| `kernels/` | C 计算库（`libnpukernels.so`） |
| `emulator/` | Python NPU 设备模拟器（`npu_device_mini.py` FP16、`npu_fp32.py` FP32） |
| `iss/` | MiniRV64 ISS（`mini_rv64.py`） |
| `firmware/` | RISC-V 固件源码 + 构建系统（默认 `TARGET=bert`） |
| `tests/` | BERT 端到端测试 + golden 生成 |
| `jimu-dse/` | 闭环固件优化系统（agent 优化） |
| `adderboard/` | 独立附加负载：两个加法 Transformer + 测试 |
| `docs/` | 平台文档（architecture / specification / firmware-guide 等） |

### 1.2 两个负载：BERT 与 adderboard

| | **BERT 负载** | **adderboard 负载** |
|---|---|---|
| 模型类型 | Encoder（BERT 单层） | Decoder（GPT / Qwen3） |
| 规模 | hidden=256, seq=64, NATIVE_DIM=128 | d=4, seq≈24, NATIVE_DIM=4 |
| 运行模式 | 一次性前向 | 自回归生成 |
| 关键算子 | LayerNorm, GELU, 标准注意力 | RMSNorm, RoPE, SwiGLU/SiLU, 权重绑定 |
| 精度通路 | 仅 FP16 | FP32 + FP16 |
| 正确性判据 | 对 numpy golden，容差内 | 任务级真值（a+b 精确已知） |
| 硬件层 | 有 HDL（Amaranth）验证 | 仅 x86 模拟器 |
| 在项目中的角色 | **默认负载 + jimu-dse 优化靶子** | 正确性/覆盖率/精度回归 + L4 参考实现 |

**adderboard 的两个模型**：
- `cosminscn_130p`（130 参数，手工构造，仅 FP32，权重硬编码在 layout）；
- `dimopep_140p`（140 参数，训练得到的 Qwen3 风格，FP32+FP16，seed 44 grokking）。

**关键点**：默认流程（`make test` / `make firmware`）跑的是 **BERT**，不触及 adderboard；
adderboard 有独立的固件目标（`TARGET=adder` / `adder_140p`）和测试入口（`adderboard/tests/`）。

## 2. 优化系统（jimu-dse）如何运作

### 2.1 核心哲学：省访存，不省算力

> **NPU 上 FLOPs 便宜、DRAM 往返贵。** 优化的唯一北极星是"降低 DRAM 流量"，
> 用**算术强度 AI = FLOPs / 搬运字节数**找瓶颈，把 AI 低（<1.0）的访存簇干掉。

内存层级类比：
- **DRAM = 楼下大仓库**（慢、大）
- **片上寄存器 VRF/MRF = 桌上小抽屉**（快、小）
- 优化 = 少跑仓库。

### 2.2 闭环流程

```
PROBE → ANALYZE → AGENT → VALIDATE → DEPLOY → (LOOP)
```

| 阶段 | 做什么 |
|---|---|
| PROBE | 跑模拟器量 DRAM 流量 + 出 DAG（微操作图） |
| ANALYZE | 找 save-load 对、低 AI 簇 |
| AGENT | 读 skill，改 `firmware/bert/bert_layer.c` |
| VALIDATE | 跑 BERT 测试，卡 max_diff + DRAM 降幅 |
| DEPLOY | 存候选、出优化后 DAG；**每轮恢复基线（改动不累积）** |

### 2.3 四个优化层级

| 层级 | 内容 | 已有 skill |
|---|---|---|
| **L1** 指令调度 | 挪顺序、删死代码、自增地址 | inc_folding |
| **L2** 片上缓存 | 中间量别往 DRAM 跑，留片上（主力） | vrf-cache |
| **L3** 微架构配置 | 精度（FP16/BFP）、tile 行列、批量 | dim-optimize（其余仅命名） |
| **L4** 有意近似+补偿 | FlashAttention 式分块 softmax/attention | 无（仅文档 + adder 实现） |

### 2.4 现有 5 个 skill

| skill | 层级/角色 | 逻辑 | 机械性 |
|---|---|---|---|
| **dag-analyze** | 分析（喂各层） | 读 DAG 找存取对 / 低 AI 簇 | 通用（概念上负载无关） |
| **inc_folding** | L1 | 把 `V_WR_DRAM+V_RD_DRAM` 存取对折成 INC 变体 | **最机械**（写死行号） |
| **vrf-cache** | L2 主力 | K/V/Q 从 DRAM 往返改为片上 `MFU_INITIAL_VRF` | 偏机械（写死函数名/offset） |
| **dim-optimize** | L3 | 多 tile→单 tile（`NATIVE_DIM==hidden`） | 中等（结构化，但绑 BERT） |
| **self-verify** | 验证 | 跑 BERT E2E，卡 max_diff<0.05 | 流程（写死测试文件） |

## 3. 当前进展

- **已跑过的优化目标（goals）**：
  - **G1**（`dram-optimization`）：DIM=2，`vrf-cache`，主指标 `total_bytes`——**不动分块**，只砍 DRAM 往返。
  - **G2**（`compute-optimization`）：DIM=4，`dim-optimize`——**消除分块**。
  - **G3**（`combined`）：DIM=4，`dim-optimize vrf-cache`，主指标 `test_pass`。
- **用户已完成 G1 + G3**，把 BERT 的分块优化掉了。结果印证（`results/run-20260708-141835-24666/p6_probe.json`）：
  `num_tiles:1, mv_mul_per_projection:1, total_projection_mv_mul:36, heads_per_tile:2, total_bytes:5472`
  —— 与 dim-optimize 的 cost model 目标一字不差。
- **L4 补偿已在 adder 固件跑通**：全项目只有 `adder_130p.c` / `adder_140p.c` 实现了分块 SPU softmax
  （`SPU_MAX_REDUCE` + `SPU_ADD_REDUCE` + `V_EXP` + `S_RECIP` + 补偿）；BERT 仍用整块 `V_FUNC`。
- **adder 移植期间修复了共享模拟器的多处缺陷**：`V_EXP`（原为空操作）、SPU 归约（改为累加）、
  `S_RECIP`/`S_SQRT`（原为桩）、`V_SIGM`（原缺失）、SRF 未清零。这些修复被整个项目共享。
- 已有一份人工报告：`jimu-dse/results/NPU固件优化重构报告.docx`。

## 4. 核心问题诊断

### 4.1 负载锁死（只服务 BERT）

- 所有 `goal.sh` 写死 `BASELINE_FILE="jimu-dse/baseline/bert_layer.c"`；
- `self-verify` / `dag-analyze` 写死 `tests/integration/test_bert_e2e.py`；
- 流水线没有"负载"这一抽象——它只认识"那个 BERT 层"。

### 4.2 固件锁死（只优化 bert_layer.c）

- skill 只改 `firmware/bert/bert_layer.c`；
- 无法作用于 adder 固件或任何其他算子控制固件。

### 4.3 skill = 机械替换，而非技能说明

- **inc_folding 本质是一个 diff**：一张"第 221 行把 A 换成 B"的表，还明说"只改列出的 8 处"。
  它编码的是**这一个文件的标准答案**，不是可迁移的规则。
- skill 写死 **行号**、**BERT 函数名**（`mvm_tiled_q`、`dot_product_attention`、`apply_layernorm`）、
  **BERT 张量地址**（`0x300=K, 0x400=V`）。
- **内部自相矛盾**：`dag-analyze` 已能通用地找出存取对，但 `inc_folding` 绕过它、改用写死行号。
  → "探测通用、改写锁死"。
- **与项目自身理念冲突**：README 声称 skill 应是带 `trigger/preconditions/transformation/cost_model`
  的结构化规格；设计文档 §5.4 更要求 L4"从算子数学 + 原语语义推导，而非模板匹配"。
  但落地的 skill 大多是写死步骤的自由文本。

### 4.4 深度绑定当前 NPU 设计（不可移植）

skill 把优化原理和这台 NPU 的 ISA/微架构焊在一起：

- 绑具体 opcode（`V_WR_DRAM_INC`/`V_RD_DRAM_INC` = 22/23）、指令格式（`SEND_SI`/`SEND_LO`）；
- 绑硬件"事实性怪癖"：**INC 变体必须用 LO 格式，用 SI 会让 Q 输出全 0**；
- 绑寄存器堆容量：`MFU_INITIAL_VRF = mem 6 = 4096 元素`、`ADDSUB_VRF_*`、`MATRIX_RF`；
- 绑寄存器号：`REG 20 = 精度模式`、`REG 1/2/3 = tile 行/列/批量`。

换一台 NPU（容量/opcode/tile 尺寸不同），现有 skill 绝大多数直接失效。
**优化原理通用，但编码只属于这台 NPU。**

### 4.5 算子粒度太粗

优化对象是"整个 BERT 层"，而非单个算子（matmul / softmax / RMSNorm / SiLU / attention）。
无法针对某个算子做针对性优化，也无法跨负载复用算子级优化。

### 4.6 硬件-固件协同闭环没闭上

项目名为 "**FW-HW co-optimization**"，但实际几乎全是**固件单边优化**：

- DAG/cluster 分析只被用来**改固件**，从没被用来**反推 ISA**；
- 缺"固件反复回退某算子 → 量化代价 → 提议新增硬件指令"的反馈支路。

### 4.7 skill 类目大量空缺

- `fusion/`（算子融合）、`tiling/`（循环分块）、`compensation/`（近似补偿）**三个类目全空**；
- L3 除 dim-optimize 外只有命名；L4 无任何 skill。

### 4.8 L3/L4 的 regime 冲突（易被误解）

- **dim-optimize（L3）** 把矩阵缩进**单 tile**——softmax 一次装得下，**不需要补偿**；
- **L4 补偿** 恰恰是**大到单 tile 装不下**时才用。
- **当前 BERT 已是单 tile（G3 之后），L4 没有优化对象**——必须先放大 benchmark 到多 tile。

### 4.9 NPU 硬件对现代 LLM 的缺口

- **无原生 RMSNorm 指令**：Qwen3 风格的 RMSNorm 回退 RISC-V 标量（有 LayerNorm 单元但 RMSNorm≠LayerNorm）；
- **无原生 SiLU/SwiGLU 指令**：用 `V_SIGM + VV_MUL` 两条拼；
- **硬件 softmax 单元不能分块**：大到装不下就得手搓补偿；
- **精度控制太粗**：只能整层切 FP16/BFP（REG 20），无按张量粒度；
- **小/尾部形状回退标量**：10 分类 logits、LM head 落到 RISC-V。

> 注：对**当前小基准**，NPU 硬件够用（vrf-cache 显示片上 VRF 仅用 0.6%，99.4% 闲置，
> 说明瓶颈是固件没用好硬件，而非硬件不足）。上述缺口在**放大到真实 LLM 规模**时才致命。

## 5. 改造目标与目标架构

### 5.1 三个解耦

| 解耦 | 从 | 到 |
|---|---|---|
| **负载解耦** | 写死 bert_layer.c | 清单驱动，任意固件 + 测试 |
| **算子解耦** | 优化"整个层" | 按算子（IR）优化，可复用 |
| **ISA 解耦** | skill 焊死 opcode/寄存器 | 模式与 ISA 绑定分离，可换 target |

### 5.2 目标架构

```
   workloads/*.yaml   operators/*.yaml   targets/npu_v10.yaml
   (负载清单)          (算子库/IR)         (NPU 目标描述)
        │                  │                    │
        └──────────────────┼────────────────────┘
                           ▼
              ┌─────────────────────────┐
              │   优化流水线(通用化)      │
              │  PROBE→ANALYZE→AGENT     │
              │      →VALIDATE→DEPLOY    │
              └─────────────┬───────────┘
             ┌──────────────┼───────────────┐
             ▼              ▼               ▼
      pattern-driven   fallback-report   HW-proposal
      skills(可移植)   (回退分析)         (反推硬件)
```

核心思想：**三份声明式配置驱动同一条流水线**；skill 拆成"模式（可移植）+ ISA 绑定（每 target 一份）"，
类比编译器的"优化 pass + 后端 backend"；新增"回退分析 → 硬件提案"的协同反馈支路。

## 7. 里程碑与执行顺序

| 里程碑 | 目标 | 关键动作 | 可验证产出 |
|---|---|---|---|
| **M0 可插拔负载** | 流水线不再 BERT 专用 | 参数化 `goal.sh`（读 workload 清单）；写 adder 清单；self-verify 参数化 | **(已完成)** 用现有 skill 跑通 adder |
| **M1 可移植 skill** | skill 脱离行号/BERT | 将 vrf-cache、dag-analyze 等改写为 pattern-driven 模式 | **(已完成)** 同一条 skill 同时作用于 bert 和 adder |
| **M2 算子库 + 融合** | 按算子优化 | 写算子 IR；做 `fusion/*` 打 AI=0.5/0.0 簇 | BERT 融合后 DRAM/指令数下降 |
| **M3 硬件反馈闭环** | 反推 ISA | 回退分析器 → 硬件提案 → 新增模拟器 op（如 RMSNorm）→ 重测 | 数据驱动的 HW 提案 + 消除的回退量 |
| **M4 扩规模 + L4** | 大算子补偿 | 放大 benchmark；移植分块 softmax→attention | 整块 softmax 跑不了的形状，分块能跑 |

### 7.1 L3 路线（现在可做，低风险）

1. **敏感度画像**：借 adder 的 FP16 研究方法，逐张量/逐层测 BERT 权重对 FP16/BFP 的敏感度。
2. **写 `hw/precision-select` skill**：按敏感度 + DRAM 代价决定每张量用 BFP/FP16，切 REG 20。
   ⚠️ 现在 REG 20 只能整层切，按张量需先确认模拟器/硬件粒度支持。
3. **验证**：max_diff 在容差内 + DRAM 降幅，跨 seq 回归。
4.（后续）tile/batch 配置搜索（REG 1/2/3）+ 预测性 cost model；泛化 dim-optimize 为形状驱动。

### 7.2 L4 路线（需先扩规模）

0. **扩 benchmark 到多 tile**（`hidden > NATIVE_DIM` 或更大 seq_len）——L4 的前提。
1. **把 V_EXP 接进 BERT 固件通路**（模拟器已支持，adder 在用）。
2. **移植 adder 分块 SPU softmax**，替换 BERT 多 tile 路径的整块 `V_FUNC/SOFTMAX`。
3. **写 `compensation/tiled_softmax` skill**（推导式，按 §5.1 四阶段：近似→合并→修正→验证）。
4. **验证**：max_diff < 容差，且确认能跑通整块 softmax 跑不了的多 tile 形状。
5.（依赖 1-4）**分块 attention**（在线/流式，FlashAttention）+ `compensation/tiled_attention` skill。
6.（收尾）`tiled_layernorm`、`bfp_tile_approx`（衔接 L3 精度）、`approx_gelu_boundary`。

### 7.3 推荐第一步

**从 M0 起步**，最小可验证、风险最低、直接打破"BERT 专用"：

1. 定义负载清单 schema，写 `bert.yaml` 和 `adder_140p.yaml`；
2. 改 `goal.sh`（或其调用脚本）**从清单读** BASELINE_FILE / 测试命令 / 形状；
3. 跑一次 `dag-analyze` 对 adder，证明侦察层天然通用。

此步不碰任何 skill 改写，却验证"负载解耦"可行，是整条路线的地基。

### 8.1 术语速查

| 术语 | 含义 |
|---|---|
| DRAM | 主存（慢、大） |
| VRF / MRF | 片上向量/矩阵寄存器堆（快、小） |
| SPU | 标量处理单元（求和/最大值等归约 + 广播） |
| AI（算术强度） | FLOPs / 搬运字节数；<1.0 = 访存受限 = 优化靶子 |
| NATIVE_DIM | 硬件原生块大小，决定 tile 尺寸 |
| save-load 对 | 存到 DRAM 又马上读回同地址（纯浪费） |
| INC 变体 | 带自增地址指针的读写指令（opcode 22/23） |
| BFP | 块浮点，一组数共享指数，省位宽 |
| 补偿（compensation） | 分块先算错、再用全局统计量修正（FlashAttention 式） |
| 融合（fusion） | 合并连续算子，中间结果不落地 |
