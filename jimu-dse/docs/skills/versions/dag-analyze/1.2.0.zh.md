# DAG 分析技能

## 输入

使用 prompt 和附件中本次运行的准确路径。闭环运行把 DAG 数据写入
`jimu-dse/results/<run>/dag_agent/`，不要假定旧的 `_out/` 路径。

按以下顺序读取：

| 优先级 | 文件 | 内容 |
|---:|---|---|
| 1 | `summary.md` | 配置、Phase 表、重复模式、低 AI 阶段和热点 Tensor |
| 2 | `phases.json` | 稳定 Phase ID、成员、输入输出及访存/FLOPs |
| 3 | `tensors.json` | Tensor 切片及其生产者、消费者节点 |
| 4 | `patterns.json` | 压缩后的重复 Phase 实例 |
| 5 | `micro_ops.jsonl` | 带稳定 ID、defs/uses 和语义标注的微操作 |
| 6 | `edges.jsonl` | 使用稳定节点 ID 表示的生产者-消费者依赖 |
| 7 | `micro_op_dag.txt` | 用于取证复核的旧版原始文本 |
| 8 | `dram_clusters.txt` | 旧版 DRAM 流量聚类表 |

`run_metadata.json` 记录 schema 版本、固件配置、ELF SHA256、数量统计和
标注方法。比较两次运行之前必须先核对它。

## 证据规则

- 优先使用 `op-000033`、`phase-0007` 等稳定 ID。
- 原始 `uses`、`defs`、事件序号和依赖边是权威证据。
- Tensor、Phase、position 和 tile 标注是启发式信息；修改前必须结合
  原始资源和固件地址宏进行复核。
- 当前无法可靠恢复 head，不能在缺少源码证据时自行推断。
- 只有固件配置和 ELF 身份均有记录时才能比较不同 DAG。

## 分析流程

### 1. 对 Phase 排序

先查看 `summary.md` 中低算术强度表，再在 `phases.json` 中确认目标：

```text
AI = compute_flops / (dram_load_bytes + dram_store_bytes)
```

低 AI、高流量 Phase 是主要访存优化目标。重复模式意味着收益可能随
position 或 tile 成倍增加。

### 2. 选择 Tensor 切片

使用 `tensors.json` 查找同时存在生产者和消费者的 DRAM Tensor 切片，
再根据稳定节点 ID 定位 `micro_ops.jsonl` 中的节点。

### 3. 证明保存-加载对

保存-加载对是相同 DRAM 地址上的 `DRAM_STORE` 和后续 `DRAM_LOAD`，
且中间不存在对该地址的写入。必须在 `edges.jsonl` 或
`micro_op_dag.txt` 中确认生产者边。

```text
op-000033 DRAM_STORE defs=DRAM[0x300]
op-000150 DRAM_LOAD  uses=DRAM[0x300]
edge: op-000033 -> op-000150 via DRAM[0x300]
```

它可能把：

```text
VRF -> DRAM -> VRF
```

改为：

```text
VRF -> 保留在 VRF -> 消费者
```

### 4. 映射回固件

1. 使用节点事件序号缩小执行位置。
2. 使用 Tensor 和地址标注定位固件地址宏。
3. 在 `firmware/bert/bert_layer.c` 中找到生产者和全部消费者。
4. 根据源码复核 position/tile 地址，不能只依赖启发式标注。

### 5. 输出 VRF 生命周期证明

修改前必须给出：

```text
Selected phase ID:
Selected Tensor slice:
Producer node:
Consumer nodes:
DRAM address:
Intervening write:
VRF allocation:
Lifetime:
Conflicts:
Expected seq2 saving:
Expected seq6 saving:
```

如果存在中间写入、VRF 活跃区间冲突，或者消费者不能直接使用缓存布局，
必须主动放弃该变换。

## 必需输出

使用稳定 ID 列出候选：

```text
Save-load pairs:
  K[pos=0,tile=0]:
    op-000033 DRAM_STORE -> op-000150 DRAM_LOAD
    address=0x300, phase=phase-0007, intervening_write=no
```

随后在一次分阶段 G1 迭代中只选择一个新的缓存层级，并在修改固件之前
输出完整生命周期证明。
