## 1. 结论摘要

Goal 1 的 `total_bytes` 实际按仿真器中的 **float32 存储元素数 × 4 B** 计分，而不是设计文档所写的 FP16 元素 × 2 B。下文的“字节”均优先指这个评分字节数。

对当前 Goal 1，可以区分三层极限：

| 层次 | 保留/放宽的约束 | 通式（评分字节） | `seq=2` | `seq=6` |
|---|---|---:|---:|---:|
| 当前 `vrf-cache` 脚本的实际可达下限 | 只消除中间张量 DRAM 往返；权重、bias、LN 参数和单位向量仍按原循环重复读 | `608S` | **1216 B** | **3648 B** |
| 扩展的 Goal 1 下限 | 仍保持每个投影、每个位置重读权重，但把 bias/LN/单位向量也跨位置缓存 | `416S+176`；若片上生成单位向量则为 `416S+160` | **1008 B**（或 992 B） | **2672 B**（或 2656 B） |
| 算法/信息传输硬下界 | 所有输入、权重和参数只读一次，所有最终输出只写一次；允许权重循环换序或片上重建 MRF | `544+32S` | **608 B** | **736 B** |

因此：

1. 若问题是“**现有 Goal 1 脚本只做 VRF 中间结果缓存，最终大约能到多少**”，建议把目标值定为 **1216 B（seq=2）/ 3648 B（seq=6）**。仓库已有通过数值验证的候选结果达到这一档，继续只找普通 save-load 对不会再下降。
2. 若允许把 Goal 1 扩展到“缓存所有循环不变量”，合理的下一档目标是 **1008 B / 2672 B**；单位向量由固件片上生成时可再降至 **992 B / 2656 B**。
3. 纯理论硬下界是 **608 B / 736 B**。它不是当前 `vrf-cache` 技能能自然产生的结果，需要改变权重调度（或把权重先缓存为向量并在片上重建 MRF），属于更强的全局数据流变换。

按代码注释中的 FP16 物理数据量理解时，上述评分值应除以 2；例如算法硬下界对应 304 B（seq=2）和 368 B（seq=6）。但 Goal 1 的脚本不会按这个数打分。

## 2. Goal 1 的优化与计分口径

`jimu-dse/goals/dram-optimization/goal.sh` 指定：

- `DIM=2`、`HIDDEN=4`、`NUM_HEAD=2`；
- 测试 `SEQ_LENS="2 6"`；
- 唯一技能为 `vrf-cache`；
- 主指标为 `total_bytes`；
- BERT 基线文件是 `jimu-dse/baseline/bert_layer.c`。

闭环脚本先把基线复制到 `firmware/bert/bert_layer.c`，随后执行 probe、生成候选、验证并以 `seq=6` 的 `total_bytes` 比较优劣。计分代码为：

```text
total_elements = vec_rd_elements + vec_wr_elements
               + mat_rd_elements + mat_wr_elements
total_bytes    = total_elements * 4
```

在本配置下：

- 一条 `V_RD_DRAM` 或 `V_WR_DRAM` 统计 `NATIVE_DIM=2` 个元素，即 **8 个评分字节**；
- 一条 `M_RD_DRAM` 或 `M_WR_DRAM` 统计 `NATIVE_DIM²=4` 个元素，即 **16 个评分字节**；
- 读掩码只改变有效数据，不减少统计的传输元素数；
- VRF/MRF 之间的片上读写、算术、softmax、GELU、LayerNorm 均计 0 DRAM 字节。

这解释了为何固件注释和设计文档称数据为 FP16，但测试输出仍写 `float32 elements` 并乘 4。评估优化结果时必须采用脚本口径。

## 3. `bert_layer.c` 的执行过程

记序列长度为 `S`，隐藏维度 `H=4`，原生维度 `D=2`，因此每个隐藏向量分成 `T=H/D=2` 个 tile；每个注意力头宽度为 2，每个 tile 恰好容纳一个头。

### 3.1 投影内核 `mvm_tiled_q`

每次计算一个位置上的 `y=W·x+b`：

1. 按列 tile `tc=0..1` 读取一个长度为 2 的输入块；
2. 对每个行 tile `tr=0..1` 读取一个 `2×2` 权重 tile 并执行 MVM；
3. 第二个列 tile 的部分和通过片上 VRF 做加法累积；
4. 两个输出 tile 分别从 DRAM 读取 bias 并相加。

所以每次投影固定产生：

- 4 次 `M_RD_DRAM`：完整读取一个 `4×4` 权重矩阵；
- 2 次输入 `V_RD_DRAM`；
- 2 次 bias `V_RD_DRAM`。

每个位置执行 Q、K、V、Self-Output、FFN Intermediate、FFN Output 共 6 个投影，因此矩阵读取为 `24S` 次，投影内部向量读取也为 `24S` 次。

### 3.2 K/V 预计算

固件先为所有位置计算 K，再为所有位置计算 V，并把每个 `H=4` 向量写到 DRAM 的保存区。这样做便于后续各 query 复用，却形成了 K/V 的 DRAM 保存—重读往返。

### 3.3 每个 query 的注意力

对每个 query 位置：

1. 计算 Q 并保存到 DRAM；
2. 对两个行 tile，逐位置读取 K，拼成 K 矩阵并计算 score；
3. 对 score 做 softmax，并把概率临时写入 DRAM；
4. 逐位置读取 V，借助 DRAM 中的单位向量把 V 重排为转置形式；
5. 重读 softmax 概率，计算 context，并写入片上累加 VRF。

K/V 的逐 query 重读导致 `O(S²)` 流量，是当前代码最明显的访存热点。

需要特别指出：当前仿真/Golden 实现的注意力矩阵只有 `D×D`，当 `S=6>D=2` 时只实际使用前 2 个 key/value 位置；固件仍循环读取 6 个位置，后 4 个位置在构建 MRF 时被截断。因此这些多余读取是可消除的，但本报告的硬下界仍按完整接口的输入、参数和所有位置输出计算，不利用测试夹具的这一截断现象“作弊”。

### 3.4 Self-Output、残差、LayerNorm 与 FFN

每个位置继续执行：

```text
Z
 -> Self-Output 投影
 -> 与原始 X 做残差加法
 -> LayerNorm 1
 -> FFN Intermediate 投影
 -> GELU
 -> FFN Output 投影
 -> 与原始 X 做第二次残差加法
 -> LayerNorm 2
 -> 最终输出写 DRAM
```

当前代码为释放流水线/VRF 端口，把 Z、Self-Output、原始 X、LN1 输出、GELU 输出和 LayerNorm scratch 多次写入再读回 DRAM。这些都是 Goal 1 的 `vrf-cache` 技能所针对的中间张量往返。

## 4. 当前源码的基线流量模型

对当前工作树中的 `jimu-dse/baseline/bert_layer.c` 逐条统计，得到：

| 流量 | 指令次数 | 来源概述 |
|---|---:|---|
| `V_RD_DRAM` | `4S²+52S` | 6 个投影的输入/bias、K/V/Q、单位向量、softmax scratch、残差和 LN scratch/参数 |
| `V_WR_DRAM` | `26S` | K/V/Q、softmax、Z、SO、残差、LN/GELU scratch 和最终输出 |
| `M_RD_DRAM` | `24S` | 每位置 6 个投影 × 每投影 4 个权重 tile |
| `M_WR_DRAM` | `0` | 无 |

代入 `D=2`：

```text
B_base(S)
= 4 × [2 × (V_RD次数 + V_WR次数) + 4 × M_RD次数]
= 4 × [2 × (4S²+78S) + 4 × 24S]
= 32S² + 1008S  字节
```

所以当前源码静态计数为：

| 配置 | 当前基线 | 二次项 | 线性项 |
|---|---:|---:|---:|
| `seq=2` | **2144 B** | 128 B | 2016 B |
| `seq=6` | **7200 B** | 1152 B | 6048 B |

仓库的 `npu-closed-loop-design.md` 和部分旧 prompt 写的是 2144 B / 6240 B，但同一文档列出的 `V_RD=456`、`V_WR=156`、`M_RD=144` 在 `D=2` 下实际恰好得到 7200 B；文档还把 `M_RD=144` 误写成与序列长度无关，而源码显然是 `24S`。因此 **6240 B 是过期或计算错误的历史值，不应作为当前源码的精确基线**。已有 probe JSON 对 `seq=2` 的 2144 B 与上述公式一致；本地 Python 环境缺少 pytest，未重新执行 `seq=6` 动态测试。

## 5. 三层理论极限的推导

### 5.1 当前 `vrf-cache` 脚本的实际可达下限：`608S` B

保持当前投影循环和参数读取方式，只把 K/V/Q/Z/SO/LN/GELU/softmax/残差等所有中间张量放在片上 VRF：

| 必须保留的流量 | 元素数 |
|---|---:|
| 每个位置重读 6 个 `4×4` 权重矩阵 | `96S` |
| 原始 X 预缓存一次 | `4S` |
| 6 个 bias，每位置各读一次 | `24S` |
| 两次 LN 的 gamma/beta，每位置各读一次 | `16S` |
| V 转置所用单位向量，每 query、每 tile 重读 | `8S` |
| 最终输出写回 | `4S` |
| 合计 | `152S` |

故：

```text
B_vrf-only(S) = 152S × 4 = 608S 字节
```

对应 1216 B（seq=2）和 3648 B（seq=6）。仓库中的历史候选 `run-20260714-111219-5577/candidate_best.c` 及 probe 结果正好达到这两个数：

- `seq=2`：矩阵读 192 元素、向量读 104 元素、向量写 8 元素，共 1216 B；
- `seq=6`：矩阵读 576 元素、向量读 312 元素、向量写 24 元素，共 3648 B；
- 旧运行日志记录 `max_diff=0`。

这说明它不是纯纸面估算，而是当前脚本边界内已经实现过的可达值。相对当前源码的 2144/7200 B，降幅分别为 **43.3%** 和 **49.3%**。

### 5.2 扩展 Goal 1：缓存循环不变量

上一步所谓“剩余不可约流量”其实仍包含可复用的只读数据：

- 6 个 bias 总共只有 `6H=24` 个元素，不必每个位置重读；
- 两次 LN 的 gamma/beta 总共 `4H=16` 个元素，不必每个位置重读；
- 两个 `2×2` 单位向量共 4 个元素，可只读一次，也可用 FILL 和写掩码片上生成；
- MFU VRF 有 4096 元素，远大于这些数据和 `S≤6` 的中间张量容量。

若单位向量只从 DRAM 读一次：

```text
元素数 = 重复权重 96S + X 4S + 输出 4S
       + bias 24 + LN参数 16 + 单位向量 4
       = 104S + 44

B_extended(S) = 416S + 176 字节
```

即 1008 B（seq=2）和 2672 B（seq=6）。若单位向量完全片上生成，再减 16 B，得到 **992 B / 2656 B**。

相对当前源码，1008/2672 B 的降幅分别为 **53.0%** 和 **62.9%**。这一档仍不改变每个位置执行 6 次投影的算术顺序，只需要增加静态参数缓存和从 VRF 装载参数的路径，风险明显低于全局权重调度变换。

### 5.3 算法/信息传输硬下界：`544+32S` B

假设所有模型参数和输入在执行前只存在于 DRAM，且它们可取任意值。要对任意输入和参数正确计算一层输出，至少必须传输：

| 数据 | 元素数 | 说明 |
|---|---:|---|
| 6 个稠密权重矩阵 | `6H²` | Q/K/V/SO/Wi/Wo |
| 6 个 bias | `6H` | 每个投影一个 |
| 两次 LN 的 gamma/beta | `4H` | 4 个长度 H 的向量 |
| 输入 X | `SH` | 每个位置一个长度 H 的向量 |
| 最终输出 | `SH` | 每个位置必须写出 |

不存在对任意值都正确、却完全不读取上述某个模型元素的实现。因此：

```text
E_min = 6H² + 10H + 2SH
      = 6×4² + 10×4 + 2S×4
      = 136 + 8S  个元素

B_absolute(S) = 4 × (136+8S)
              = 544 + 32S 字节
```

即：

- `seq=2`：152 元素，**608 B**；
- `seq=6`：184 元素，**736 B**。

达到这一极限需要让 6 个权重矩阵也只跨 DRAM 一次。可行的数据流有两种：

1. **投影循环换序**：按 `projection → weight tile → position` 执行。一个权重 tile 进入 MRF 后，连续处理所有位置，再加载下一个 tile；每个位置的部分和保存在 VRF。
2. **权重向量缓存**：把 96 个权重元素一次读入大容量 VRF；每次需要某个 `2×2` tile 时，通过 `MEM_VEC_TO_MAT_ROW` 在片上重建 MRF。它增加片上指令数，但不增加 Goal 1 的 DRAM 指标。

`S=6` 时，即使同时缓存输入、参数、Q/K/V、残差和若干临时量，总需求也只是数百个元素，显著小于 4096 元素的 MFU VRF；SI 的 VRF 地址字段为 16 位，也不是瓶颈。因此该下界从容量上可达。不过它违反当前 `vrf-cache` 技能“不要修改权重加载”的约束，而且要谨慎保持 FP16 舍入和 tile 累积顺序，不能视作当前脚本无需改造就会收敛到的目标。

## 6. 建议的优化目标与优先级

### 建议一：为现有 Goal 1 设置明确的停止线

当前脚本若坚持只消除中间张量 DRAM 往返，应把 `seq=6` 的目标设为 **3648 B**。达到该值后，所有剩余流量都来自原始输入、最终输出、重复权重、bias/LN 参数和单位向量；继续寻找普通 save-load 对不会产生收益。

### 建议二：加入“循环不变量缓存”子目标

在 `vrf-cache` 技能中新增三类模式：

1. bias 跨位置缓存；
2. LN gamma/beta 跨位置缓存；
3. 单位向量只初始化一次或片上生成。

这一阶段的 `seq=6` 目标应设为 **2672 B**（保守）或 **2656 B**（片上生成单位向量）。它是最值得作为下一版脚本目标的值：收益明显，且不必改变矩阵乘的外层调度。

### 建议三：把权重驻留/循环换序作为独立高级技能

若要逼近 **736 B**，应新增区别于普通 `vrf-cache` 的 `weight-stationary` 或 `projection-loop-interchange` 技能，并同时约束：

- 每个权重元素从 DRAM 只读一次；
- 每个输入元素只读一次；
- 只允许最终输出写 DRAM；
- 保持每个输出的 `tc` 累积顺序和 FP16 舍入点；
- 对 `seq=2`、`seq=6` 都验证全部位置，而非只检查最后位置。

## 7. 风险与口径说明

1. **评分字节不等于 FP16 物理字节。** 当前测试使用 float32 数组保存 DRAM，并把元素数乘 4；若未来仿真器改为真实 2 B 口径，所有本文评分值应折半。
2. **历史 6240 B 基线不自洽。** 当前源码和文档中的操作次数都推导出 7200 B。报告以当前源码为准。
3. **注意力在 `seq=6, D=2` 时被截断。** 当前 Golden 明确只使用 `min(seq_len, native_dim)` 个 key/value。极限估计没有通过只输出最后位置、忽略其他位置或依赖固定测试数据来进一步压低流量。
4. **容量足够不等于实现自动正确。** LayerNorm 会占用特定 VRF bank，MRF 会被注意力重排覆盖，写掩码也会影响数据保存；实际实现需要完整的 VRF 生命周期分配。
5. **闭环停止条件不是理论收敛判据。** 脚本默认最多 5 轮，并按相对 run-start 的阈值判断，不能保证自动发现上述全局最优数据流。

## 8. 最终判断

对“Goal 1 访存优化脚本的理论极限”最有操作意义的答案是分层给出：

- **现有脚本/技能边界内：1216 B（seq=2），3648 B（seq=6）**；
- **增加循环不变量缓存后：约 1008 B / 2672 B，最好可到 992 B / 2656 B**；
- **不受现有技能边界限制的算法硬下界：608 B / 736 B**。

若需要为下一轮自动优化设置单一目标，建议先用 **`seq=6 <= 2672 B`**：它比当前脚本已达到的 3648 B 更有挑战，又不要求一次性引入高风险的全局权重调度重构。736 B 应作为长期架构级上限，而不是当前 `vrf-cache` 脚本的直接验收线。
